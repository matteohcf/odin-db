# 0040. AI query assistant

- Status: Accepted
- Date: 2026-10-18

## Context

Writing MongoDB filters is the main hurdle for occasional users; Compass offers natural
language queries through a cloud model. odin-db's users often work on data they may not send
anywhere, and the feature must stay optional: some will never want it.

## Decision

- **Engines.** A query is generated by a model run in-process with llama.cpp (`llama-cpp-2`,
  Metal on macOS, CPU elsewhere) or by the user's Ollama over its HTTP API. The choice, the model
  and the Ollama address are settings; with no model chosen nothing is downloaded or loaded,
  and the assistant can be hidden entirely.
- **Crate.** The feature lives in `crates/ai` (`odin-ai`), independent of Tauri like core, so
  llama.cpp's build stays out of `odin-core` and its tests.
- **Catalog.** Models are a fixed catalog in `catalog.rs`, pinned by size and SHA-256 like
  mongosh (ADR-0014), downloaded from Hugging Face into the app data `models/` directory.
  Downloads resume from a `.partial` file (pausing is cancelling) and install only when the hash
  matches. A model is recommended from the machine's memory.
- **Privacy.** The model gets the collection name, the request, and the sampled field paths with
  their BSON types (`FieldHint`); sampled values are dropped before the request leaves the
  webview, and the IPC type has no field for them.
- **Output.** Generation is constrained to one JSON object `{filter, sort, projection, limit}`:
  a GBNF grammar for llama.cpp, the equivalent JSON schema for Ollama. Core then parses it as
  extended JSON, converts strings compared with date or ObjectId fields to those types, and
  rejects `$where`, `$function`, `$accumulator`, `$out` and `$merge` anywhere. The query fills
  the query bar after review and runs only on request.
- **Quality.** `crates/ai/tests/eval.rs` scores catalog models on about 100 requests over five
  schemas (ignored by default; it downloads models). At the time of writing Qwen2.5 Coder 1.5B
  answered 85% correctly in about 2 s on an M3, Qwen2.5 Coder 0.5B 55%, Qwen3.5 2B 65%.

## Alternatives considered

- **A cloud API** — rejected as the default: it sends schema and requests off the machine and
  needs an account. Ollama covers users who want larger models.
- **Bundling a model** — adds 0.5–3 GB to every installer for an optional feature.
- **Sampling values for the prompt** — improves matching on enum fields but leaks data.
- **Aggregation pipelines** — not yet: small models are far less reliable at them, and a
  pipeline can write (`$out`, `$merge`).

## Consequences

- Building the app needs CMake and a C++ toolchain; clean builds take a few minutes longer.
- The first query after launch loads the model (seconds); it then stays in memory until the
  feature is turned off, the model deleted, or the app quits.
- Catalog entries must be re-pinned when a model is updated upstream; the eval decides the
  recommendation.
