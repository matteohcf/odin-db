# odin-db

Open source desktop client for MongoDB (free alternative to Studio 3T).
Tauri 2 (Rust) + React + TypeScript. Windows, macOS, Linux.

**Status: Milestone 0** (platform spike, see `docs/milestone-0.md`). Every structural decision is recorded in `docs/adr/`.
Read the relevant ADR before touching an area. A change that contradicts an ADR
requires a new ADR that supersedes it — never silently diverge.

## Repository layout

```
apps/desktop/            React UI (Vite)
  src/app/               composition root: providers, layout, wires features together
  src/features/<name>/   one folder per feature: api/ components/ hooks/ lib/ store/ locales/
    index.ts             the feature's public API (the only importable surface)
  src/components/        app-level shared components (EJSON cell, code editor, theme menu)
  src/lib/               framework-free helpers: IPC, EJSON display, shell syntax, formatting
  src/dev/               dev-only code (mock backend), never shipped
  src-tauri/             Tauri host: thin commands only
    src/commands/<domain>.rs
    capabilities/        Tauri permission sets (minimal)
    binaries/            sidecars (fetched by script, git-ignored)
crates/core/             all MongoDB/domain logic. NO Tauri dependency.
  src/<domain>/          connection, documents, query, indexes, aggregation,
                         transfer, backup, shell, storage (added as built)
packages/ui/             shared shadcn/ui components (no app logic)
packages/bindings/       src/bindings.gen.ts GENERATED by tauri-specta
docs/adr/                Architecture Decision Records
```

## Dependency rules (enforced in review and CI)

- `crates/core` never depends on `tauri*`. It must compile and test standalone.
- `src-tauri` commands are thin: deserialize → call core → map `CoreError` to `IpcError`. No business logic, no MongoDB calls.
- `packages/ui` never imports from `apps/*` or `packages/bindings`.
- The UI talks to the backend only through `packages/bindings`. Never call `invoke()` with string command names.
- `packages/bindings` is generated. Never edit it by hand. Regenerate with `pnpm bindings`.
- Features import other features only through their `index.ts`. Dependencies point one way: `connections` and `documents` may use `workspace`; `workspace` knows no feature (the app passes render props). Only `src/app` wires features together.
- Imports use the `@/` alias for `src/`; relative imports only within the same folder subtree.

## Core concepts

- **Rust is the source of truth** for every type crossing IPC (ADR-0005).
- **IPC** (ADR-0006): request/response = command. Long operation = command + `Channel<T>` + `OperationId`, cancellable via `cancel_operation`. App-wide notifications (connection state) = typed events.
- **Streaming in core**: core APIs take a `tokio::sync::mpsc::Sender<T>` and a `CancellationToken`. `src-tauri` bridges them with `ipc::spawn_streaming_operation`, which registers the operation, forwards data as `StreamEvent::Data` and ends with exactly one terminal event. On the UI side always use `startStream` (`src/lib/streaming.ts`) and `createFrameBatcher` (`src/lib/frame-batcher.ts`). Core never knows about Channels.
- A Tauri `Channel` has no consumer acknowledgement: fast producers must be pull-based (fetch on demand) or flow-controlled, never fire-and-forget.
- **BSON over IPC is canonical Extended JSON v2** (ADR-0007). Never relaxed EJSON, never plain JS numbers for BSON numeric types. Type changes on round-trip are data corruption.
- **One `mongodb::Client` per connected profile**, owned by `ConnectionManager` in core (ADR-0008). The UI only holds a `ConnectionId`.
- **Results paginate via server-side cursors** held in core, fetched in batches on scroll (ADR-0009). Never emulate with hidden skip/limit.
- **Result paging is pull-based** (ADR-0025): `find_documents` → `fetch_more_documents` → `close_cursor`, driven by `createResultsController`. Never stream query results over a channel.
- **The grid renders cells from data** (ADR-0026); TanStack Table owns columns only.
- **Editable text is mongosh syntax** (`toShellSyntax` / `parseShellDocument`); display text is `describeEJson` / `compactEJson`. Never round-trip edits through the display format.
- **Frontend state** (ADR-0010): TanStack Query for backend request/response data, Zustand for UI-only state. Streaming results live in per-tab stores, flushed once per animation frame. Never copy backend data into Zustand.
- **Read-only mode and all safety checks are enforced in Rust**, never only in the UI (ADR-0017).

## Rust conventions

- Edition 2024, toolchain pinned in `rust-toolchain.toml`.
- Errors: `thiserror` enums per domain, unified in `CoreError` (with a stable `ErrorKind` for the UI). No `anyhow` in core. No `unwrap()`/`expect()` outside tests (clippy enforces it; `clippy.toml` allows them in tests).
- IPC-facing core types derive `specta::Type` only behind the `specta` feature: `#[cfg_attr(feature = "specta", derive(specta::Type))]`.
- IDs are newtypes (`ConnectionId`, `ProfileId`, `OperationId`), never bare `String`/`Uuid`.
- Secrets use a wrapper type with a redacting `Debug` impl. Connection strings are redacted before logging.
- Logging with `tracing` (structured fields, no `println!`).
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo deny check` must pass.

## TypeScript conventions

- `strict` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.
- No `any`. No non-null `!` without a comment explaining why it cannot be null.
- Components: function components, named exports, one component per file. File names `kebab-case.tsx`.
- Every user-visible string goes through i18next (ADR-0024). English is the source language.
- UI primitives come from `packages/ui` (shadcn). Do not hand-roll a button, dialog, menu, etc. Add components with the shadcn CLI from `packages/ui` (`pnpm dlx shadcn@latest add <name>`) and follow the official docs; class merging uses the official `cn` package, re-exported from `@odin-db/ui/lib/utils`.
- Biome for lint and format. knip must report no unused exports or dependencies.

## Testing

- Core: unit tests next to code. Integration tests in `crates/core/tests/` against real MongoDB via `testcontainers` (6.0, 7.0, 8.0). Run with `cargo nextest`.
- UI logic: Vitest. Keep logic in framework-free modules (`lib/`, controllers, stores) so it is testable without React.
- UI review: `pnpm --filter @odin-db/desktop dev:web` in a browser uses the in-memory mock backend (ADR-0027). Check light and dark themes. Update `src/dev/mock-backend.ts` whenever a command changes.
- E2E smoke: `tauri-driver` on Linux and Windows.
- A bug fix includes a test that fails without the fix.
- See ADR-0020.

## Commands

```
pnpm install          install JS deps
pnpm dev              run the desktop app in dev mode
pnpm --filter @odin-db/desktop dev:web   UI only, in a browser, with the mock backend
pnpm bindings         regenerate packages/bindings from Rust
pnpm check            every gate CI runs: Biome, tsc, knip, Vitest, rustfmt, clippy, cargo test
pnpm format           apply Biome fixes and formatting
pnpm test:integration core integration tests against real MongoDB (requires Docker)
pnpm build            production build of the desktop app
```

## Git and contributions

- Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`, `ci:`), enforced by commitlint. Scope = area (`core`, `desktop`, `ui`, `bindings`, `ci`).
- One logical change per PR. CI must be green: checks, tests, bindings up to date.
- Licensing: MIT OR Apache-2.0. Contributions are accepted under the same terms (inbound = outbound), no CLA.
- New dependency → justify it in the PR. `cargo-deny` rejects incompatible licenses.
