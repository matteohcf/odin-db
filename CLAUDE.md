# odin-db

Open source desktop client for MongoDB (free alternative to Studio 3T).
Tauri 2 (Rust) + React + TypeScript. Windows, macOS, Linux.

**Status: pre-release.** V1 features are built; release packaging is next (platform spike results in `docs/milestone-0.md`). Every structural decision is recorded in `docs/adr/`.
Read the relevant ADR before touching an area. A change that contradicts an ADR
requires a new ADR that supersedes it — never silently diverge.

## Repository layout

```
apps/desktop/            React UI (Vite)
  src/app/               composition root: providers, layout, wires features together
  src/features/<name>/   one folder per feature: api/ components/ hooks/ lib/ store/ locales/
    index.ts             the feature's public API (the only importable surface)
  src/components/        app-level shared components (EJSON cell, code editor, theme menu)
  src/hooks/             app-level shared React hooks
  src/lib/               framework-free helpers: IPC, EJSON display, shell syntax, formatting
  src/dev/               dev-only code (mock backend), never shipped
  src-tauri/             Tauri host: thin commands only
    src/commands/<domain>.rs
    capabilities/        Tauri permission sets (minimal)
    binaries/            sidecars (fetched by script, git-ignored)
crates/ai/               AI query assistant: model catalog, downloads, llama.cpp and Ollama engines. NO Tauri.
crates/core/             all MongoDB/domain logic. NO Tauri dependency.
  src/<domain>/          connection, documents, query, indexes, aggregation,
                         transfer, backup, shell, storage (added as built)
packages/ui/             shared shadcn/ui components (no app logic)
packages/bindings/       src/bindings.gen.ts GENERATED by tauri-specta
docs/adr/                Architecture Decision Records
```

## Dependency rules (enforced in review and CI)

- `crates/core` and `crates/ai` never depend on `tauri*`. They must compile and test standalone; `ai` may use `core`, never the reverse.
- `src-tauri` commands are thin: deserialize → call core → map `CoreError` to `IpcError`. No business logic, no MongoDB calls.
- `packages/ui` never imports from `apps/*` or `packages/bindings`.
- The UI talks to the backend only through `packages/bindings`. Never call `invoke()` with string command names.
- `packages/bindings` is generated. Never edit it by hand. Regenerate with `pnpm bindings`.
- Features import other features only through their `index.ts`, and dependencies point one way:
  - `workspace` and `results` know no other feature (`workspace` gets render props from the app);
  - `documents` and `aggregation` build on `results` and open `transfer` dialogs; `documents` shows `ai`'s Ask button; `indexes` stands alone;
  - `ai` (the query assistant) uses `workspace` only, to open its settings page;
  - `collection` (the collection tab) composes `documents`, `aggregation`, `schema`, `indexes` and `changes` (the live feed) with `connections`;
  - `shell` (the shell tab) uses `connections` for the profile and its connection;
  - `backups` (history and schedules) uses `connections` and `backup`; `connections` opens it through `workspace` only;
  - `monitor` (the server status tab) and `users` (users and roles) use `connections` for the profile and its connection; `monitor` opens `indexes`' create dialog for the index advisor;
  - `settings` (the settings tab) reads `results` and `documents` stores, uses `updates` for its update row and `ai` for model downloads; preferences themselves live in `src/lib/settings.ts` so any feature can read them;
  - `compare` (collection and schema compare) uses `results` for the document diff;
  - `diagram` (the database diagram tab) uses `connections` for the connection and `workspace` for its tab model;
  - `connections` may use `workspace` to open tabs, and `backup`, `transfer` and `compare` for its dialogs; only `src/app` wires the top level together.
- Imports use the `@/` alias for `src/`; relative imports only within the same folder subtree.

## Core concepts

- **Rust is the source of truth** for every type crossing IPC (ADR-0005).
- **IPC** (ADR-0006): request/response = command. Long operation = command + `Channel<T>` + `OperationId`, cancellable via `cancel_operation`. App-wide notifications = typed tauri-specta events (`src-tauri/src/events.rs`), e.g. `ConnectionHealthChanged` from the driver's topology events.
- **Streaming in core**: core APIs take a `tokio::sync::mpsc::Sender<T>` and a `CancellationToken`. `src-tauri` bridges them with `ipc::spawn_streaming_operation`, which registers the operation, forwards data as `StreamEvent::Data` and ends with exactly one terminal event. On the UI side always use `startStream` (`src/lib/streaming.ts`) and `createFrameBatcher` (`src/lib/frame-batcher.ts`). Core never knows about Channels.
- A Tauri `Channel` has no consumer acknowledgement: fast producers must be pull-based (fetch on demand) or flow-controlled, never fire-and-forget.
- **BSON over IPC is canonical Extended JSON v2** (ADR-0007). Never relaxed EJSON, never plain JS numbers for BSON numeric types. Type changes on round-trip are data corruption.
- **One `mongodb::Client` per connected profile**, owned by `ConnectionManager` in core (ADR-0008). The UI only holds a `ConnectionId`.
- **Results paginate via server-side cursors** held in core, fetched in batches on scroll (ADR-0009). Never emulate with hidden skip/limit.
- **Result paging is pull-based** (ADR-0025): `find_documents` → `fetch_more_documents` → `close_cursor`, driven by `createResultsController`. Never stream query results over a channel.
- **The grid renders cells from data** (ADR-0026); TanStack Table owns columns only.
- **Query bar fields are single-line CodeMirror editors** with context-aware suggestions from sampled field paths (ADR-0031); aggregation stages get the same through `CodeEditor`'s `completions`, with the previous stage's output as fields (ADR-0032). `queryContext` decides where the cursor is, `queryCompletionSource` what to offer, `useQueryCompletions` localizes it.
- **Editable text is mongosh syntax** (`toShellSyntax` / `parseShellDocument`); display text is `describeEJson` / `compactEJson`. Never round-trip edits through the display format.
- **Frontend state** (ADR-0010): TanStack Query for backend request/response data, Zustand for UI-only state. Streaming results live in per-tab stores, flushed once per animation frame. Never copy backend data into Zustand.
- **Read-only mode and all safety checks are enforced in Rust**, never only in the UI (ADR-0017).
- **File dialogs open from Rust** (`tauri-plugin-dialog`); the webview never sends a file path. Imports use an opaque token returned by `choose_import_file`.
- **Transfers write atomically**: exports go to `<file>.partial` and are renamed when complete.
- **The shell is mongosh in a PTY** (ADR-0030), with credit-based flow control: the UI acknowledges output after xterm.js renders it, and sends input one write at a time. Read-only cannot be enforced inside mongosh, so the tab warns instead.
- **Backups are recorded and schedulable** (ADR-0034): every mongodump goes through `src-tauri/src/backups.rs::run_backup`, which records it in the history before anything can fail; the scheduler lives there too.
- **User preferences** live in one typed, persisted store, `useSettings` (`src/lib/settings.ts`). A new setting is a field with a default there, a row on the settings page, and a reader where it applies (read with `getState()` at use time when nothing needs to re-render). Window-wide effects (zoom, language, editor font) are applied by `useApplySettings` (ADR-0035).
- **Every long operation is registered** in `OperationRegistry`, scheduled backups included: quitting while any runs asks first (`src-tauri/src/quit.rs`, `QuitRequested`), then cancels them. Open tabs except shells are restored on launch (`restorableTabs`).
- **SSH tunnels** (ADR-0036): `ssh::open_tunnel` with host keys pinned per profile; `connection::route` rewrites the URI to the tunnel. Tools get `ConnectionHandle::uri`, never the profile's string. A host key error carries its fingerprint in `IpcError.detail`.
- **Large deployments** (ADR-0037): the connection tree is one flat, virtualized list: `buildTreeRows` (`features/connections/lib/tree-rows.ts`) turns profiles, databases and collections into rows, so a cluster with thousands of collections renders only what is in view. A row component never renders its children. Grid columns are virtualized too; catalog-wide reads use `browse::catalog` (bounded concurrency), never one request per database.
- **GridFS** (ADR-0038): a `<bucket>.files` collection gets download and upload; dialogs open from Rust.
- **Query profiler** (ADR-0042): `profiler::{status, set_status, entries}` over the `profile` command and `system.profile`; changing the level needs a writable profile.
- **Collection compare** (ADR-0041): `compare::compare` matches by `_id` in two bounded passes (left batches looked up on the right with `$in`, then right ids alone); field order is ignored, types are not. `compare::sync` reuses the same scan to insert, replace or delete on the right (read-only refused).
- **AI query assistant** (ADR-0040): optional; llama.cpp in-process or Ollama, chosen in settings. Only field paths and types reach a model (`fieldHints`), output is grammar-constrained and checked in Rust (`parse_answer`), and fills the query bar without running. Catalog models are pinned by SHA-256.
- **Live changes** (ADR-0046): `changes::watch` streams a collection's change stream, lossy (dropped events are counted) and as a passive operation that quitting does not ask about.
- **Schema compare** (ADR-0045): `schema_compare::compare_schemas` matches two databases' collections by name, fields by sampled path and types, indexes by keys and options; missing indexes can be created on the other side.
- **Index advisor** (ADR-0044): `advisor::advise` reads slow operations from `getLog` and any profiler that is on, keeps scans, groups them by the ESR index they need and flags existing indexes the planner ignores.
- **Quick charts** (ADR-0048): the results' Chart view plots loaded rows only; `results/lib/chart.ts` picks the chart from the field's role (date → line, text → bars, number → histogram or scatter). Recharts via shadcn `chart`, lazy. GeoJSON point fields go on an offline SVG map (ADR-0049), never a tile server.
- **Diagram annotations** (ADR-0047): drawn references, hidden inferred ones, notes and areas (which carry the nodes inside them when dragged) live in `useAnnotations` (local storage, per database) and merge with the analysis through `annotate`; layout ignores them.
- **Database diagram** (ADR-0043): `diagram::database_diagram` samples each collection and infers references from data (ObjectId values found as `_id` elsewhere), not names. The tab draws it with React Flow and dagre, loaded lazily; dragged positions persist per database.
- **Automatic updates** (ADR-0039): `check_for_update` at launch (setting `checkForUpdates`), `install_update` as a registered long operation; nothing installs without a click.
- **Shortcuts are customizable** (ADR-0050): never match `SHORTCUTS.x` directly; use `useShortcut(id)`, `matches(keybinding(id), event)` in handlers and `useKeybindingLabel(id)` for labels.
- **Long operations in the UI** go through `useOperation` (`src/hooks`): it handles Stop before the id arrives and cancels on unmount. Progress events are lossy (`try_send`); results come in one final event.

## Rust conventions

- Edition 2024, toolchain pinned in `rust-toolchain.toml`.
- Errors: `thiserror` enums per domain, unified in `CoreError` (with a stable `ErrorKind` for the UI). No `anyhow` in core. No `unwrap()`/`expect()` outside tests (clippy enforces it; `clippy.toml` allows them in tests).
- IPC-facing core types derive `specta::Type` only behind the `specta` feature: `#[cfg_attr(feature = "specta", derive(specta::Type))]`.
- IDs are newtypes (`ConnectionId`, `ProfileId`, `OperationId`), never bare `String`/`Uuid`.
- Secrets use a wrapper type with a redacting `Debug` impl. Connection strings are redacted before logging.
- Logging with `tracing` (structured fields, no `println!`).
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo deny check` must pass.

## TypeScript conventions

- `strict` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.
- No `any`. No non-null `!` without a comment explaining why it cannot be null.
- Components: function components, named exports, one component per file. File names `kebab-case.tsx`.
- Every user-visible string goes through i18next (ADR-0024). English is the source language; every `en.json` key also needs its Italian `it.json` translation in the same change (ADR-0035, enforced by a test).
- Never put `TooltipTrigger asChild` (or any Radix trigger with `asChild`) directly on another stateful Radix component (Switch, Checkbox…): the trigger's `data-state` overwrites theirs. Wrap them in a `span`.
- UI primitives come from `packages/ui` (shadcn). Do not hand-roll a button, dialog, menu, etc. Add components with the shadcn CLI from `packages/ui` (`pnpm dlx shadcn@latest add <name>`) and follow the official docs; class merging uses the official `cn` package, re-exported from `@odin-db/ui/lib/utils`.
- Biome for lint and format. knip must report no unused exports or dependencies.

## Testing

- Core: unit tests next to code. Integration tests in `crates/core/tests/` against real MongoDB via `testcontainers` (6.0, 7.0, 8.0). Run with `cargo nextest`.
- UI logic: Vitest. Keep logic in framework-free modules (`lib/`, controllers, stores) so it is testable without React.
- UI review: `pnpm --filter @odin-db/desktop dev:web` in a browser uses the in-memory mock backend (ADR-0027). Check light and dark themes. Update `src/dev/mock-backend.ts` whenever a command changes.
- UI checks: `apps/desktop/e2e/*.mjs` are Playwright scripts against that mock backend; `pnpm --filter @odin-db/desktop e2e [name ...]` runs them while `dev:web` is up. A UI feature adds or extends one.
- E2E smoke: `tauri-driver` on Linux and Windows.
- A bug fix includes a test that fails without the fix.
- See ADR-0020.

## Commands

```
pnpm install          install JS deps
pnpm dev              run the desktop app in dev mode
pnpm --filter @odin-db/desktop dev:web   UI only, in a browser, with the mock backend
pnpm --filter @odin-db/desktop e2e       Playwright UI checks (needs dev:web running)
pnpm bindings         regenerate packages/bindings from Rust
pnpm check            every gate CI runs: Biome, tsc, knip, Vitest, rustfmt, clippy, cargo test
pnpm format           apply Biome fixes and formatting
pnpm test:integration core integration tests against real MongoDB (requires Docker)
pnpm build            production build of the desktop app
scripts/build-database-tools.sh <target>   build the bundled mongodump/mongorestore (needs Go)
```

## Git and contributions

- Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`, `ci:`), enforced by commitlint. Scope = area (`core`, `desktop`, `ui`, `bindings`, `ci`).
- One logical change per PR. CI must be green: checks, tests, bindings up to date.
- Licensing: MIT OR Apache-2.0. Contributions are accepted under the same terms (inbound = outbound), no CLA.
- New dependency → justify it in the PR. `cargo-deny` rejects incompatible licenses.
